# Backend Standards — Spring Boot (DDD + Hexagonal)

## Architecture & Layout
- Follow **DDD + Hexagonal**: `adapter/` (web, db, mq) ↔ `application/` (services, use cases) ↔ `domain/` (entities, VOs, domain services) ↔ `ports/` (interfaces) ↔ `infrastructure/` (impls).
- Package: `com.<org>.<domain>.<service>.<layer>`. Keep domain free of Spring/framework imports.
- Prefer immutability; domain logic in domain services, not controllers or repositories.

## API Design
- **REST + JSON**. Version endpoints: `/v1/...`.
- Define/maintain **OpenAPI**; generate clients/tests from it. Use DTOs at edges (no entities over the wire).
- Validation with `jakarta.validation` annotations on DTOs; fail fast with a single **Problem+JSON** error schema (RFC 7807).
- Pagination (limit/offset or cursor), idempotency for PUT/POST where applicable.

## Persistence & Transactions
- Migrations: **Flyway** (forward-only, idempotent scripts).
- Repositories implement **ports**; no domain awareness of JPA.
- Set `spring.jpa.open-in-view=false`. Prefer explicit fetch plans to avoid N+1.
- Transactions at **application** boundary (`@Transactional`). Keep domain methods side-effect free.

## Messaging & Integration
- Publish/consume **domain events** via adapters; use a canonical event envelope (id, type, occurredAt, payload, correlationId).
- Outbox pattern for exactly-once semantics; idempotent consumers.

## Resilience & Performance
- Timeouts everywhere (HTTP/DB). Use **Resilience4j** for retries, circuit breakers, bulkheads, and rate limits.
- Avoid blocking calls on reactive threads; bound thread pools.

## Observability
- **JSON logs** (mask PII). Always include `correlationId`/`traceId`, `service`, `operation`, `durationMs`, `status`.
- **OpenTelemetry** traces/metrics; http server/client spans; DB and MQ instrumentation.
- Health: `/actuator/health` (liveness/readiness), info, metrics; export Prometheus.

## Security
- OAuth2/OIDC; method security with `@PreAuthorize`.
- Validate/encode untrusted input; no PII in logs.
- Secrets from vault/parameter store only; **never** in source or env-committed files.
- Enforce TLS 1.2+; set secure headers on adapters.

## Configuration
- Externalize via env/params; profiles: `local`, `dev`, `stage`, `prod`.
- Feature flags for risky changes; default OFF.

## Testing Strategy
- **Unit**: JUnit 5 for domain/services; no Spring context.
- **Web tests**: `@WebMvcTest` or `MockMvc` for controllers.
- **Integration**: `@SpringBootTest` + **Testcontainers** for DB/broker.
- **Contract/Functional**: **Karate** from OpenAPI (happy + error cases).
- Deterministic tests only (no sleeps or network in unit tests). Coverage gate (changed files) ≥ **80%**.

## Build, Packaging & Runtime
- Gradle + **JaCoCo**; fail build if coverage gate unmet.
- Docker/Buildpacks image; small base; run as non-root; healthcheck.
- SBOM & vulnerability scans in CI. Supply SLSA provenance when available.

## Code Style & Quality
- MapStruct for DTO↔domain mapping; avoid manual reflection.
- Avoid static util “god” classes; prefer composition.
- Logging levels: `ERROR` (actionable), `WARN` (unexpected), `INFO` (coarse), `DEBUG` (dev only).
- Use `Optional` at API boundaries, not as fields; prefer records for simple DTOs in Java 21.

## Do / Don’t
- ✅ Domain pure; validation at edges; explicit ports; idempotency.
- ❌ No DB from controllers; no entities in responses; no secrets/PII in logs; no long methods (>50 LOC) or massive classes (>400 LOC).

## When Copilot generates code, require:
1) A short **edit plan** (files to add/modify + tests + commands).  
2) DTOs + mappers, not entities.  
3) Unit + Karate tests, and README updates (run/test commands).

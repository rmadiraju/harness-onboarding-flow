# Frontend Standards — React / Next.js

## Foundations
- **TypeScript required**; strict mode on. Node LTS. React 18+ / Next 14+ preferred.
- Directory: `app/` or `src/` with `components/`, `features/`, `lib/`, `styles/`, `tests/`.
- Use a design system (tokens/components) or Tailwind/CSS Modules consistently.

## Architecture
- Separate **presentational** vs **container** components. Business rules live in **services/hooks**, not UI.
- Data layer via **RTK Query** or a typed client; no direct `fetch` in components.
- Use `ErrorBoundary` + route-level error pages. Centralized API error handling and toasts.

## State & Forms
- Local state with hooks; global domain state via **Redux Toolkit** (slices) or minimal context.
- Forms with **react-hook-form** + **Zod/Yup** schema validation; show inline errors, disable submit while pending.

## Routing & URLs
- Next App Router with file-based routes; use `generateMetadata` for SEO.
- Keep URLs as the single source of truth for filters/pagination; use search params helpers.

## Testing
- **Unit**: Jest or Vitest + **@testing-library/react** (no shallow).  
- **a11y**: add **jest-axe** checks for complex components.  
- **E2E**: **Playwright**; smoke suite for main routes and critical flows; use fixtures for auth and data.  
- Coverage gate (changed files) ≥ **80%**.

## Accessibility & UX
- Keyboard-first navigation; focus states; landmarks (`main`, `nav`, `header`, `footer`).
- Use semantic elements; ARIA only when needed. All interactive elements must be reachable via keyboard and have labels.
- Color contrast meets WCAG AA.

## Security
- **Never** interpolate untrusted HTML; if unavoidable, sanitize then `dangerouslySetInnerHTML`.
- Tokens in **httpOnly cookies**; no secrets in client code.  
- Set CSP & trusted image/script sources (Next: headers config).  
- Escape/encode all user content; validate inputs at boundaries.

## Performance
- Code-split via `dynamic()`; memoize heavy components (`React.memo`, `useMemo`, `useCallback`).
- Optimize images (`next/image`); prefetch critical routes.
- Avoid large, synchronous work in the render path; use workers for CPU-heavy tasks.

## Data & API Layer
- Create typed clients (`lib/api/*`) with runtime validation of responses (Zod).
- Always handle `loading`, `error`, `empty` states; render skeletons/placeholders.
- Cache and invalidate predictably (RTK Query tags; SWR keys). Never store secrets in localStorage.

## Styling
- One approach per repo (Tailwind **or** CSS Modules **or** styled-system).  
- Co-locate styles with components. No unused globals.

## Telemetry
- Instrument page views and key actions (OTel Web / analytics).  
- Mask PII before sending telemetry.  
- Log client errors centrally; include correlation id if present.

## Linting & Format
- ESLint with plugins: `react`, `jsx-a11y`, `@typescript-eslint`, `testing-library`, `unused-imports`, `sonarjs`.
- Prettier enforced; CI must fail on lint errors.

## Do / Don’t
- ✅ Components pure; hooks for side effects; typed API layer; a11y first; test critical interactions.
- ❌ Direct `fetch` in UI; state explosion in context; inline secrets; `any` types; snapshot tests as the only tests.

## When Copilot generates code, require:
1) A short **edit plan** (files + tests).  
2) Component + tests (Testing Library) + Playwright spec for the happy path.  
3) a11y checks, types, and a README snippet with run/test commands.
